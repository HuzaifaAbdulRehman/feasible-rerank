# Exact baseline. experiments/exact.py solves the McCormick-linearised MILP that the
# heuristics are measured against, and tests/test_exact.py checks it against exhaustive
# enumeration. Both import pulp at module level, so a missing pulp is not a skipped
# test -- pytest fails collection and the entire suite exits non-zero.
#
# Upper bound is deliberate: PuLP 3.x already warns that constructing LpVariable
# directly is deprecated and becomes an error in 4.0, which is the form exact.py uses.
# Without the cap a future PuLP release breaks the exact baseline silently at install
# time rather than at review time.
#
# Not in pyproject.toml's [project] dependencies: only qubo_rerank/ is packaged, and the
# library itself never imports pulp.
pulp>=2.7,<4

# Development. pytest>=7.0 is required for the `pythonpath` ini option that lets a
# bare `pytest` import the package from a checkout.
pytest>=7.4
coverage>=7.0
ruff>=0.6

# Deliberately absent: recbole, torch, pyqubo.
#
# The plan called for RecBole's ItemKNN to supply relevance scores and the item-item
# similarity matrix. That model is a shrunk cosine similarity plus a top-k
# neighbourhood truncation -- no gradients, no GPU. Reimplementing it against
# scipy.sparse costs ~40 lines (benchmarks/loader.py) and removes a ~2.5 GB dependency
# from the critical path. The on-disk data format stays RecBole-compatible, so the real
# thing can be swapped back in as a loader change if a future experiment needs a model
# that actually trains.
#
# pyqubo was never imported: dimod builds the BQMs directly, and dimod.generators
# .combinations already provides the exact-k cardinality constraint.
